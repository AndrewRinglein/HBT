# Viewer code review — 2026-09-04

*A read of the whole package at viewer `12fecd9`, engine `4932fde`. Every claim
below was **reproduced by running it**, not inferred; each carries the file:line
and, where it is a bug, the measurement that proves it. Nothing here is fixed

**Headline:** one real user-visible bug that hits every attack in every battle,
five tests that cannot fail, four drawing defects, and one architectural rule
the package needs and does not have. The bug and the blind test have the same

## A · The scrub silently deletes every impact effect — REAL BUG

**`src/fold.js:488`** — `foldTo()` nulls `S.ATTACK` and `S.AOO`:

```js
S.AIM = null; S.FIRING = null; S.TRIGFLASH = null; S.ATTACK = null; S.AOO = null
```

`S.ATTACK` is the declared attack (`{kind, dt, dmg}`). It is deliberately durable
— `fold.js:31` says so: *"outlives AIM, so an area attack's second and third hits
still know what struck them"* — and it carries **no clock**, so `foldTo` can
rebuild it perfectly. It is thrown away anyway. Then `fold.js:225` gates all
impact on it: `if (S.ATTACK && U[e.target])`.

`seek()` (`viewer.js:246`) sets `V.S = foldTo(...)`. So: **drag the scrub bar to
any point between an `attack.declared` and its `attack.hit`, press Step, and the
blow lands with no impact FX, no `CRIT!`, no camera kick** — only the damage
numeral, so it reads as a silent hit.

Measured across all 21 library logs, folding each attack in sequence versus
folding it after a scrub to just before it:

```
attack.hit / attack.miss compared:                  678
LOST the impact FX after a scrub:                   678   (100%)
LOST the CRIT! word + camera kick after a scrub:      7   (every crit)
LOST the attack-of-opportunity marking:              91
```

`attack.miss` is the same story (`fold.js:241` — *"ONE place says miss"* — reads
`S.AIM`, which is legitimately clock-stamped, so after a scrub the miss is drawn
nowhere at all).

**Why no test caught it.** `tools/verify.mjs:130` strips both fields before
comparing the pure fold against the pumped one:

```js
const strip = S => JSON.stringify({ ...S, AIM: null, FIRING: null, TRIGFLASH: null, ATTACK: null, AOO: null, subjectId: null, subjectMode: null })
```

`ATTACK` and `AOO` were added to that list **by me, in this session**, to make a
failing check go green — the exact move `CLAUDE.md` forbids (*"a failing test is
a finding; adjusted the assertion is not a written reason"*). `verify.mjs:523`
even documents the workaround in a comment instead of filing the finding. The
`AOO` half of the fold bug is mine too (2026-09-03); the `ATTACK` half predates
this session.

**The fix is not to restore the strip.** `foldTo` should clear *only* clock-
stamped state (`AIM`, `FIRING`, `TRIGFLASH` — all stamped from the pump's `now`),
keep `ATTACK` and `AOO`, and the strip list should shrink to match.

## C · Drawing bugs

**C1 · `syncAuras` rim tiles never update — `board.js:186`.** The cache key is
`hex + '|' + hue`; the `edge` flag that picks the tile's opacity (`30` vs `1c`)
is *not* in the key. When a holder steps, a hex that was the rim becomes
interior, the key is unchanged, `L.AURA.has(k)` is true, and the tile keeps the
bright rim opacity for the rest of the battle. The aura's edge smears across
every hex the holder has ever had at exactly `radius`. A backwards `seek()` does
not repair it.

**C2 · `corpseGone`'s animation is never seen — `board.js:161` vs `viewer.js:220`.**
`fold.js:414-415` deletes the corpse *and* cues `corpse.gone` in the same fold;
the pump then calls `render()` synchronously, `syncCorpses` sees the corpse is
gone and removes the node — in the same tick the 360 ms fade started. All four
`how` branches (raised / eaten / consumed / destroyed) are dead code.

**C3 · `pushFloat`'s timer is unregistered — `board.js:232`.** It is the only
`setTimeout` in the file not added to `V.fx.timers` (compare :370, :414, :420,
:431, :461, :533, :535). `seek()` calls `clearFloats()`, which deletes every
`FLOAT_SLOTS` key; the orphaned timers then fire for up to 1.96 s and decrement
the *new* counters, so floats stack at identical offsets. The scrub fires
`seek()` on every `input` event, so a drag produces dozens.

**C4 · Animation races — `board.js:311/316/486` and `viewer.js:238`.** Two
compounding problems:

- `Animation.cancel()` dispatches its `cancel` event **asynchronously**. So
  `shove` cancels a walk, sets `E.walk` to itself, and a frame later the *walk's*
  `oncancel` runs `E.walk = null` and re-arms the CSS transition under the
  running shove. `seek()` and `dispose()` then cannot cancel it.
- Board animation durations are wall-clock; the pump's waits are divided by
  `V.speed * 0.75`. At ×1 the pump waits 1.33× the animation — safe. **At ×2 it
  waits 0.67×, at ×4 0.33×**, so the next beat lands inside the running walk
  every time and the race above becomes routine. This is a Law 3 problem in
  spirit: *"the DUR table is the whole pacing model"*, and `board.js` has a
  second, unscaled pacing model beside it.

**C5 · `seek()` during a hitstop leaves tokens frozen — `board.js:431`.** The
resume lives only in the hitstop timer; `cancelBeats` clears it without
resuming, and a paused animation still applies its effect. A scrub landing in the
70–140 ms window can leave a token stuck mid-rise at `rotate(-80deg) scaleY(.4)`
with no render able to fix it (`syncUnits` writes `style`, which the paused
animation overrides).

## D · Architecture

**D1 · There is no rule for what `foldTo` may discard.** A is the instance; this
is the class. The rule the package needs, and does not state: ***`foldTo` clears
only state stamped from the pump's `now`; everything else must reconstruct.***
Without it, the next durable field added to the fold will be nulled by habit and
the same bug returns. It belongs in `VIEWER-CONSTITUTION.md` under Law 3 (which
already says the fold has no clock of its own).

**D2 · `strip()` is where coverage goes to die, and nothing says so.** Every
field nulled there has *zero* test coverage, silently. Today that is seven
fields, including `subjectId`/`subjectMode` — which drive the panel, the action
bar and the camera (`subject.js`, `panel.js:22`), and which `fold.js:489`
*rewrites* inside `foldTo`, so pure can never match pumped by construction.
Concretely untested: `crit.effect` and `deathbed.stood` deliberately hand the
panel to the target; a scrub to just after either hands it back to the actor and
no check can see it. The strip list should carry a one-line justification per
entry, and adding to it should be as deliberate as adding an exemption.

**D3 · The pure-vs-pumped check is close to tautological.** `drive()`
(`verify.mjs:114`) reaches the pumped state by repeated `v.step()`, which folds
the same events in the same order through the same `fold()`. The only things
that can differ are the `now` argument and `expireAim()` — and all four affected
fields are stripped. The check that would actually bite is
**`foldTo(EV, i)` versus stepping to `i`, at arbitrary `i`** — which is exactly
the comparison A fails, 678 times.

**D4 · The fold's context is too narrow for the data model that grew around it.**
`ctx` is only `{UD, SN}` (`viewer.js:110`), so the fold structurally cannot
resolve kit-granted actions the way `actions.js:32` does. Measured: of 30
self-targeted `power.used` events, **19 find no definition** — every one a kit
grant (`power.knight-shield.block`, `power.holy-symbol.heal`), all present in
`static.json.actions`. The branch is dead rather than visibly wrong today only
because the following `status.applied` cues the same flourish.

**D5 · Two lists for one concept.** `u.injuries` (`fold.js:50`, names harvested
from `crit.effect`) and `u.badges` (`fold.js:58`, the engine's real badge list)
now sit side by side, drawn in two different places in the panel
(`panel.js:188` and the badges block). `GLOSSARY.md` is explicit that Badge is
the container and Injury is one of its player-facing nouns. The viewer having
its own parallel list predates the engine's badges and should fold into them.

**D6 · The exemptions law has a silent bypass — `verify.mjs:91`.**
`} catch (e) { /* no committed copy yet */ }` swallows *any* failure of
`git show HEAD:tools/exemptions.json`, disabling the "may only shrink" rule with
no message: git absent, unborn HEAD, a tarball copy, or **renaming the file
itself**. Law 9 is "never swallow a failure". Separately, the diff compares
*key sets*, not entry bodies — so a computation can be added by appending
"AND …" to an existing entry's `computes` text, which **has already happened**
(the `danger` entry now covers two distinct computations).

**D7 · `gate.mjs:48`'s Law 5 scan is non-recursive** while the door probe
(:28) and the Law 6 hue probe (:55) both recurse. `src/` is flat today, so
nothing escapes; the first `src/fx/` directory silently exits the law.

**D8 · The `ai.*` split has no stated rule.** `ai.mode`, `ai.override`,
`ai.hunts` are folded; `ai.tookHighGround`, `ai.denied` are ignored. Five
siblings, split two ways, with the ruling living in a `Set` literal in a test
file. A sixth `ai.*` event has no rule to follow. (Same for
`knockback.blocked`, which is ignored while `move.stopped`, `aoo.skipped` and
`attack.cancelled` are all folded — a blocked shove is as visible a fact as a
stopped move.)

**D9 · Page weight: 9.3 MB, and 544 KB of it is one table.** `hexDist` is
**55% of `static.json`**, and the 24×24 board alone is 432 KB (576² bytes,
base64) — shipped to every viewer whether or not a 24×24 battle is opened.
`attacks` + `abilities` (155 KB) are a *proven subset* of `actions` and are
dumped alongside it. Both are cheap wins: compute `hexDist` per board on demand
from `geometryOf` at mount, and drop the two subset tables.

## E · Dead code and cosmetics

- **`board.js:497`** — `E.img.animate([{filter:'none'},{filter:'none'}], {duration:1})`
  in `badgeBeat`. Animates nothing to nothing; it is also the only use of `E.img`
  there, so the guard above it (`!E.img.animate`) gates the beat on a capability
  it never uses. **Mine, 2026-09-04.**
- **Dead unit state**, set and never read: `u.mvBase` (`fold.js:50`),
  `u.moveMods` (`:166` — and `activation.begin.movementMods` is present on 19
  real events and discarded), `u.surgeChance` (`:433`, not declared in `mkUnit`
  so the row shape varies), `S.encounter.objectives` (`:140`),
  `S.encounter.result` (`:150`).
- **`e.stoppedBy` is read and never carried** (`fold.js:318`). No `knocked` event
  in any log has it — 15 events, all `{from, to, asked, hexes}`. Either an engine
  debt or a stale read; the float always says plain `KNOCKED`.
- **`fold.js:286`** recomputes `after - before` as a status fallback and labels
  the cue `of: 'after'`, which is not the field it used. Never fires today (all
  466 `status.applied` carry `amount`), so verify's verbatim catch has never seen
  it; if it ever fired, the catch would fail with a message pointing at the wrong
  field.
- Four registered timers never delete themselves from `V.fx.timers`
  (`board.js:370, 414, 420, 431`), so the Set is not the "pending beats" it
  claims to be. `traverse`'s bob (`:315`) is untracked and survives `seek()`.
  `drawAim` builds and appends an SVG before its `if (!AIM) return`
  (`:793-797`). `drawEdges` divides and multiplies by a literal `1` (`:916`).
- **`verify.mjs`** leftovers: `const { mountBattleViewer } = { mountBattleViewer: null }`
  (:361), an unread `pendingBefore` (:382), a shadowed `createState()` (:198).
- **`verify.mjs:149`** — the 24-activation render sweep asserts nothing and its
  markup is overwritten before `allHTML()` collects it. It is a does-not-throw
  smoke pass under a comment implying coverage.
- **`verify.mjs:608`** — the aura check's message says "should tint N" and the
  assertion is `tiles >= want.size`. A runaway radius passes. It also skips 17 of
  21 battles silently, and its "no aura round a fallen holder" arm is gated on
  `holders.length === 1`, true in exactly one battle.
- **`verify.mjs:552`** — an unconditional `break` means the "no unit wears a skull
  it didn't earn" check examines one unit per battle.
- **`fakedom.mjs:126`** — `_flush` drains timers and *then* finishes animations,
  so an `onfinish` that schedules cleanup leaves a timer this flush will not
  drain. That directly affects the "no timers pending after dispose()" check.

## What I would fix, in order

1. **A** — stop `foldTo` discarding `ATTACK`/`AOO`, shrink `strip()` to match,
   and add the `foldTo(i)`-vs-`step-to-i` check from **D3** so the class of bug
   cannot come back. One fix closes the bug, the blind spot and the rule.
2. **B1** (`|| true`), **B2**, **B3** — tests that lie are worse than absent.
3. **D6** — a named law with an unconditional silent bypass.
4. **C1, C2, C3** — visible, cheap, independent.
5. **C4** — scale board animations by `V.speed`, and make `oncancel` guard on
   `E.walk === anim` before nulling. Needed before anyone reviews at ×2 or ×4.
6. **D9** — 544 KB of distance tables and 155 KB of duplicate registries.

**Not bugs, checked and clear:** no CSS `filter` sits in the 3D transform chain
(all six sites are leaves); no cross-battle cache survives a `H.load()` (`V` is
rebuilt per mount and every removal path in `syncLayers`/`syncCorpses` is
diff-correct); no `if (U[…])` guard drops a real state change on any of the 21
logs (48 guarded event types, zero misses); `syncAuras` is O(auras × hexes) and
costs tens of microseconds — its defect is C1, not cost; the exemption marker
scan matches all nine markers exactly; and the float-verbatim catch
(`verify.mjs:135`), the hitstop bounds check, the emphasis-ladder three-way
equality and the four-angle NO-HELD enforcement are all genuinely sharp.
