### 3.1 The standing bug list — `REVIEW-2026-09-04.md`

A full read of the package, every claim reproduced by running it. **Start with
§A.** In priority order:

1. **§A — the scrub deletes every impact effect.** `foldTo` (`fold.js:488`)
   discards `S.ATTACK` and `S.AOO`, which are durable and clock-free. Measured:
   **678 of 678** attacks lose their FX after a scrub, all 7 crits lose `CRIT!`
   and the camera kick, 91 AoOs lose their marking. The fix is three parts and
   closes the bug, the blind spot and the missing rule together: stop nulling
   reconstructible state in `foldTo`; shrink `verify.mjs:130`'s `strip()` to
   match; add the `foldTo(i)`-vs-`step-to-i` check (§D3) that would have caught
   it.
2. **§B1–B3 — tests that cannot fail.** A literal `|| true` (`verify.mjs:548`);
   three types on the mandatory-coverage list with no assertion anywhere;
   `night.fell`'s banner test skipped by an index guard while its guard passes.
3. **§D6 — the exemptions "may only shrink" law has an unconditional silent
   `catch`** (`verify.mjs:91`), defeated by a file rename or a missing git.
4. **§C1–C3** — aura rim tiles never update; `corpseGone`'s fade is removed in
   the tick it starts; `pushFloat`'s unregistered timer corrupts float stacking
   after every scrub.
5. **§C4** — board animations are wall-clock while the pump's waits are

## 4 · The shape of the code

```
src/fold.js       PURE. state × event → state + CUES. No DOM, no clock, no colour.
src/viewer.js     mountBattleViewer(el, data, opts) → the component + the pump + DUR
src/board.js      the DOM half: ground, painted layers, corpses, auras, tokens, floats,
                  banners, the Deathbed modal, hexVFX bridge, camera, edge bubbles
src/panel.js      the focus panel (stats, badges, facts)   src/actionbar.js  the 12-slot bar
src/actions.js    kitOf/actionsOf — the engine's row shape, read where the engine put it
src/theme.js      EVERY colour on the board            src/subject.js  whose panel/bar/camera it is
src/harness.js    the REPLAY page ONLY: dropdown, transport, rail, log, file-drop, page fit
src/engine.ts     THE DOOR      src/sheet.ts  unit sheets + the dumped tables (owed to the engine)
tools/play.mjs    play ONE export headlessly — every event folded/ignored/UNKNOWN, every cue
```

Three things to hold in your head:

1. **The fold is pure and returns cues.** Adding a beat is a cue kind in
   `fold.js` and a case in `playCues`. **`foldTo` must clear only clock-stamped
   state** — the rule the package needs and does not yet state (REVIEW §D1).
2. **The harness is above the component.** `mountBattleViewer()` has no mode.
3. **The pump owns time.** Events carry order; `DUR` carries duration — except
   that `board.js` animations are a second, unscaled pacing model beside it
   (REVIEW §C4).

## 5 · Working here in a sandbox

`gate.mjs --land` and `build-viewer.mjs` take ~2.5 minutes and **exceed the
600 s tool cap only when chained**; run them detached and poll:

```
(nohup sh -c 'node tools/gate.mjs --land > /tmp/gate.log 2>&1; echo EXIT $? >> /tmp/gate.log' >/dev/null 2>&1 &)
sleep 170; tail -3 /tmp/gate.log
```

Re-exporting 21 battles takes ~3 minutes the same way. `git` in the mounted
folder occasionally leaves a stale `.git/index.lock` that cannot be removed
without the delete permission — ask for it rather than working around it.

Publishing the artifact intermittently fails with "Socket is closed" or
`ECONNRESET`; **wait 100–150 s and check `action: "list"` before republishing**,
or you will create a duplicate.
