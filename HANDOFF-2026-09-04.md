## 7. Sandbox notes (Cowork)

- The mount **refuses `unlink`**: git leaves `.git/index.lock` after every write, and the
  next git call dies on it. Put a shim on PATH that moves `.git/*.lock` (and
  `refs/heads/*.lock`, `objects/*.lock`) into `.git/_stale_locks/` before and after each
  call — `/sessions/<id>/bin/git` this session. `git stash`, `git checkout -- <file>` and
  `tar x` over an existing file all fail; **overwrite in place**
  (`git show HEAD:f > f`, `tar -xOf t f > f`). Confirmed again 2026-09-04 evening: a
  bare `rm` of a file you just created returns *Operation not permitted*. The shim works,
  but git still prints its own `unable to unlink` warnings and leaves `tmp_obj_*` files
  under `.git/objects/` after every commit — **both are noise, not failure**; check the
  exit code and `git log -1`, not the warnings. `.git/_stale_locks/` accumulates and
  nothing can empty it.
- Background processes die with the tool call. Run the gate in the **foreground** with a
  10-minute timeout; a landing takes ~2½ minutes.
- A real browser is available: `node engine/node_modules/playwright-core/cli.js install
  chromium`, then `apt-get download libxdamage1`, unpack it, and run node with
  `LD_LIBRARY_PATH` pointed at it. Worth it — the whole after-battle flow was driven and
  screenshotted that way, and it catches what the text smoke cannot.
- The gate's commit subject is stripped of backticks and `$` (`tools/gate.mjs`): an
  unbalanced backtick in a spec's first 72 characters killed a commit mid-landing.
- Park work-in-progress **outside the tree** before a landing — the gate commits
  `git add -A`, so a second item's files get swept into the first item's commit.
