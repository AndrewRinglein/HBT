## What the engine did

Engine `5603c40` (`board.variable-size` c5085c1, `board.deploy-edges` c354793),
under Angela's ruling of 2026-09-03 (`engine/DECISIONS.md`, "board formats"):

- four board formats — **8×8 duel · 16×8 dungeon segment · 16×16 standard · 24×24 horde**
- **`WIDTH`, `HEIGHT`, `HEX_COUNT` and the free hex functions are gone** from
  `engine/src/core/hex.ts`; the geometry is `geometryOf(board)` and rides on the
  Ctx as `ctx.geo`
- hex ids are **`row × width + col` on that board** — an id is meaningless without
  the board it came from
- `map.loaded` now carries `width`, `height` and `deploy`, and the default
  deployment is **heroes WEST, enemies EAST**

Written up in `engine/EVENTS-FOR-THE-VIEWER-2026-09-03.md` §10, which names this
package's two-line repair explicitly.

## Why the test is shaped the way it is

`src/ui/slice.ts`'s `boardSvg` was already written off `v.width`/`v.height`, so a
non-square board draws correctly and heroes on the left plot on the left. The bug
the removal could have hidden is quieter: a hex id decoded at the **wrong width**
puts a unit on the wrong hex and the screen is plausibly, silently wrong. So the
test pins the identity — `hex === row × width + col`, one terrain per hex,
every unit inside the board — which holds at all four formats and names none of
them. Nothing in it says 16.

## Not done, on purpose

- **`BattleView` does not carry `deploy`.** The screen plots what `unit.enter`
  said and takes no side of the board for granted, so it does not need to know
  which edge is whose. If a later screen wants to *label* the edges, that is a
  widening of the view type and it should be asked for, not assumed.
- **No kingdom map uses a non-standard format.** Whether any Territory should
  fight on the dungeon or duel board is a content and design question, not this
  repair's; it is not a switch until someone wants it.
