## Sandbox notes for whoever runs the gate from Cowork

- The mount refuses `unlink`: git leaves `index.lock` after every write. A `git` shim on
  PATH that moves `.git/*.lock` into `.git/_stale_locks/` before and after each call makes
  the gate land. `git stash`, `git checkout -- <file>` and `tar x` over existing files all fail;
  overwrite in place (`git show HEAD:f > f`, `tar -xOf t f > f`).
- Background processes die with the tool call; run the gate in the foreground with a
  10-minute timeout. A landing takes ~2½ minutes.
- The gate's commit subject is now stripped of backticks and `$` (`tools/gate.mjs`): an
  unbalanced backtick in a spec's first 72 characters killed the G9 commit between
  `git add -A` and the ledger.
- Work on more than one item at a time must be parked out of the tree before a landing:
  the gate commits `git add -A`, and a later item whose files were swept into an earlier
  commit fails "brought its own tests".
