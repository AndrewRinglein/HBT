## 3. How landings work in this sandbox (the reaper protocol)

`node tools/gate.mjs <id> --land` **runs every pre-land check to the end here**
(~3 min) and commits — then the host's 178 s command cap kills it inside the
post-land audit (the suite rerun), before the seal line, the run-log line and
the `--amend`. The state it leaves: commit made; `.state/backlog.json` and
`.state/ledger.md` modified but uncommitted. Finish by hand, exactly as the
gate would:

1. `npx vitest run --reporter=dot` (≤120 s) and `npx tsx tools/baseline.mts | diff - .state/baseline.hash` on the committed tree.
2. Set `gauntlet` on the backlog row (`not passed — N flag(s) warned` from the check list; the seal is never `passed` by hand), `landings++` in `.state/gauntlet.json`, append the post-audit paragraph and the `IRON GAUNTLET:` line to the ledger, append the run-log JSON line.
3. `git add .state GAME-BUILDER.html && git commit --amend --no-edit`, then correct the backlog `sha` and ledger heading to the **amended** sha (the gate records the pre-amend one — so do its own landings; note it).
4. `cp GAME-BUILDER.html ../GAME-BUILDER.html`.

If the gate is killed **before** committing (it happened once, inside a
30-file kill-switch run), rerun the missing check by hand, then `git add` the
item's files explicitly and commit with the gate's message form, and write the
backlog/ledger/run-log entries yourself. Every hand landing today says so in
its ledger entry.

**Before every gate run:** stash the foreign work-in-progress, because the gate
does `git add -A`:
`git stash push -u -- CLAUDE.md .claude/skills/visual-replay/SKILL.md .claude/skills/create-enemy-art tools/field-geometry.mts src/sim/coverage.ts`
— and pop it after. Check `git stash list` is empty when you stop.

**Bash calls here cap at ~178 s.** `npm test` takes ~100 s; run it alone.
`pkill -f vitest` kills your own shell (the command line matches); don't.

## 4. Gotchas found this session

- **`.state/backlog.json` is the gate's file.** Add rows by `JSON.parse` →
  `push` → `JSON.stringify(b, null, 1)`. A hand-rolled unicode-escape regex
  once escaped every hyphen and a later `indexOf` on the id missed, so a
  landing's status was written onto the wrong row (`ai.attack-choice`). The
  gate's dependency check caught it. Parse, don't regex.
- **Two other chats commit into these repos concurrently** (a content chat: S45–S52,
  the Waystation, enchants; a kingdom session filed backlog rows; a viewer session is
  editing `engine/CLAUDE.md` and retiring the old replay rig). Re-read a content file
  immediately before editing it; ship via `content/ship.mjs` (never write the pack by
  hand); commit only your own files by path. Their dirty files as of this handoff:
  engine `CLAUDE.md`, `.claude/skills/visual-replay/SKILL.md`,
  `.claude/skills/create-enemy-art/` (untracked), `tools/field-geometry.mts`,
  `src/sim/coverage.ts` (untracked); content `FUNCTIONS.md`, `gen/functions.json`,
  `hbt-codex.html`; ~10 root docs.
- **`ship.mjs` runs `assemble.mjs`** — `hbt-content.json` is rebuilt from `settled.json`.
  Editing `settled.json` without shipping leaves the pack stale.
- **Tests assert pipeline agreement, never frozen content numbers.** Every test that
  reads a hero's kit reads `fieldedDef(id)`, not `UNITS[id]` (bare). Every Law 10
  rewrite carries its reason at the edit; the ledger lists them per landing.
- **The probe's `ACTED` set** (`tools/probe.mts`) must know an event kind before an
  item whose only footprint is that event can pass gate 1 — `unit.equipped` was added
  today. Widening it is stricter, not looser.
