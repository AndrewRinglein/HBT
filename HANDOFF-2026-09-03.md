## 1 · What this is, in five sentences

The viewer **draws what happened and never decides**. It is one component —
the standalone replay page today, the battle screen inside the game later —
that folds every frame out of the engine's event log; if a fact is not in the
log or in the read-only content, it is not on screen. It became its own package
and its own nested git repository on 2026-09-02 (`THREE-PACKAGES-PLAN.md` stage
1, ruled by Andrew), a sibling of `engine/` and `kingdom/`, importing the engine
through one door. It has a constitution of seven laws, each with a check that
fails when the law is broken. The one generated page is
`viewer/BATTLE-VIEWER.html`, published as the artifact

## 3 · The shape of the code

```
src/fold.js       PURE. state × event → state + CUES. No DOM, no clock, no colour.
src/viewer.js     mountBattleViewer(el, data, opts) → the component + the pump + DUR
src/board.js      the DOM half: ground, tokens, floats, hexVFX bridge, camera, edge bubbles
src/panel.js      the focus panel        src/actionbar.js  the 12-slot bar + stamina
src/theme.js      EVERY colour on the board          src/subject.js  whose panel/bar/camera it is
src/actions.js  src/projection.js  src/icons.js  src/log.js   — pure helpers
src/harness.js    the REPLAY page ONLY: dropdown, transport, rail, log, file-drop, page fit
src/engine.ts     THE DOOR (types + read-only content)   src/sheet.ts  unit sheets (owed to the engine)
```

Three things to hold in your head:

1. **The fold is pure and returns cues.** `{k:'float', kind:'damage', dt, text,
   n, of}` — it says *what* a beat is and *which event field* its number came
   from; the board decides the colour and plays it. Adding a beat is a cue kind
   in `fold.js` and a case in `playCues`.
2. **The harness is above the component.** Anything replay-only lives in
   `harness.js`; `mountBattleViewer()` has no mode, no `if (replay)`. The
   kingdom will mount the same component with none of that chrome (stage 3).
3. **The pump owns time.** Events carry order; `DUR` carries duration. A move
   folds as one beat (`stepMove`) and the token traverses under one easing. The
   fold's lingering highlights are stamped from a **beat clock** (wall time ×
   speed) so they last the same number of beats at ×⅓ and ×4.

## 5 · How to work here without breaking it

**The loop.** Edit `src/` → `node tools/gate.mjs` (check only, ~50 s) → when it
passes and you mean it, `node tools/gate.mjs --land` → commit → publish the page
to the artifact URL above. Never hand-edit `BATTLE-VIEWER.html` or `generated/`.

**Add a check for every change.** Every beat in this package has an assertion in
`tools/verify.mjs` that fails if the beat regresses. That is the house style and
it has caught real bugs three times in two days: a peek that quietly moved the
remembered camera, two borrowed status hues, a `+-5` on a negative crit.

**The fake DOM is not a browser.** `tools/fakedom.mjs` records animations and
queues timers; `win._flush(ms)` runs them and finishes animations. It has no
layout — `getBoundingClientRect` is constant and `clientWidth` is 1920 — so
verify pins the board wrap to a design viewport (`sizeWrap()`). Anything that
depends on real measurement is **not** covered; that is what Andrew's eyes are
for.

**Traps that have bitten, all still true.** No CSS filters in the 3D scene ·
every wrapper in the 3D chain needs `preserve-3d` · the ground must be the
stage's FIRST child · anything low on a token needs `translateZ` or the hex in
front shears it · never redraw floats from a render · `.pip` was already taken ·
a native `<select>` cannot open in the artifact pane · verify against the script
and stylesheet, never the whole file (base64 art contains every substring) ·
never hardcode a `+` on a delta (`sgn()`).

**Publishing quirks.** Large payloads intermittently fail with "Socket is
closed" or a connection reset; wait 90–150 s and retry — check the artifact list
before republishing, since it may have gone through. A 404 on the artifact URL
means the browser is signed out.
