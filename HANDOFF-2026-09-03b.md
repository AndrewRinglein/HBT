## 3. How this run worked the sandbox (read before landing anything)

The mounted folder is I/O bound: the suite is 118 s there and 19 s on local
disk, and the gate (two suite runs) cannot finish under the host's ~178 s cap.
So: `git clone` the root, engine and content repos to `/tmp/hobat-root/`
(same tree shape — `content-check` reads `../*-SETTLED.md`, `ship.mjs` reads
`../art`; symlink `art` to the mount), copy `node_modules`, and run the gate
there in one call. Sync back with a fast-forward pull into the mounted repos
(`/tmp/sync.sh` did engine, content and root; it never touches the other
chats' dirty files). The clone is gone with the sandbox; the mount is truth.

**Gotchas found:** file deletion in the mount needs one approval
(`allow_cowork_file_delete`) or `.git/*.lock` accumulates; the gate's
`logRun('landed')` line is written AFTER its amend, so `git checkout` of
`.state/gauntlet-log.jsonl` before the next gate discards it — this run's
landed lines are in the ledger and the backlog, not all in the run-log;
a module-level counter in the runner broke same-seed determinism until the
uid was read off the state (now tested); the kill-switch seam did not strip
unit auras until `disable.ts` learned them.
